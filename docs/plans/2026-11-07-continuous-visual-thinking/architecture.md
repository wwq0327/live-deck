# 架构与迁移

状态：待实施设计。需求以 [README.md](README.md) 为准，具体字段以 [protocol.md](protocol.md) 为准。

## 1. 总体结构

```text
麦克风 / 文本回放
        ↓
输入适配 → Transcript Ledger（按 segment_id/revision 替换，保留历史）
        ↓                                    ↑ 后续转写或讲话纠正
Scheduler（单个在途语义请求 + 合并待处理输入，不丢 final）
        ↓
POST /api/understand → Flash → 完整、短 JSON 操作
        ↓
校验请求版本、输入证据和操作 → 原子更新 Semantic Store
        ↓
Presenter（当前语义 → 可见场景；保持画面时仅更新后台）
        ↓
Keyed DOM/SVG Renderer（保留元素身份，局部更新与语义动画）
```

输入、模型请求与动画不互相阻塞。识别更新不等于出页，收句也不等于换场景。

## 2. 模块边界

建议新模块放在 `public/semantic/`，使用原生 ESM `.js`，便于浏览器与 Node 测试复用。现有项目已使用 `type: module`，无需构建工具。

| 模块（建议名） | 职责 | 不承担的职责 |
| --- | --- | --- |
| `transcript.js` | 输入事件账本、替换与排序、待消费输入 | 不从关键词决定因果 |
| `store.js` | 语义图、证据、原子操作、版本、有限历史 | 不直接操作 DOM |
| `scheduler.js` | 合并、上下文、请求、冲突重算、指标 | 不按一句话强制翻页 |
| `renderer.js` | 按稳定 ID 更新节点、关系与标签 | 不调用模型，不解释原话 |
| `layouts.js` / `theme.css` | 关系布局、样式及动态规则 | 不随页数随机换布局 |
| `app.js` | 模式启动、现有输入桥接、控制、诊断 | 不复制一套麦克风或 ASR 引擎 |
| `semantic-director.mjs` | 提示词、模型调用、结构校验、失败状态 | 不复用旧的造页启发式推断关系 |

文件名可在首个实现 PR 中等价调整；协议和行为变更必须同步文档，不能悄悄另起一套字段。

## 3. 输入账本

在创建 ASR 音频段时就生成 segment ID 与顺序，不等网络响应回来才编号。同一段的 partial 是前缀的替换版本，不是新的内容追加。final 替换该段草稿并封口；后来的旧 partial 不得覆盖 final。

必须在异步调用前捕获 `epoch/segment_id/order/revision`。不能在回调里读取此时已改变的全局 `state.seg` 当作原请求身份。

新模式需把“接收转写”和“调用旧 commit 出页”分开：partial/final 先入账，再由调度器处理。现有 ASR 仍是分段音频上的多次识别，不对外宣称已替换为原生流式识别模型。

音频切段仍可存在；上一个音频段的语义场景可以跨到下一个段。final 乱序返回时按音频顺序合并，不能把返回顺序当成讲话顺序。

## 4. 语义调度

初始策略：同一时刻最多一个语义请求；新输入马上入账，等待区合并为最新 revision，但保留每段未消费 final 及其来源。

启动参数建议：合并窗口 300ms；有语义文字变化后最迟 800ms 安排一次可用请求；若请求在途则返回后立即处理待输入，不按每个 token 发请求。这是可调的初始策略，不是新模式已测性能。

没有句号或静音也能触发。重复 partial 不触发；明显未完成的因果或转折可返回 `hold`，但输入仍被记录。不能仅靠“所以”等连接词决定关系。

**不因每次新输入都取消在途请求。** 持续讲话下，这会让系统永远没有可提交结果。若原请求的来源 revision 仍有效、base graph 未变，可以提交它，再接着处理新增输入。

**不把所有 final 排成逐页出场队列。** 可以在一次请求内合并理解多个 final，但模型必须明确报告已消费哪些 revision；中间信息仍是必需输入，不能只截取最后一句。旧队列语义仅保留在旧模式。

## 5. 版本、修正与消费

- `epoch`：重置、模式切换或新的会话使旧结果失效。
- `graph_version`：成功应用一批原子操作后递增，保护人工修正和其他已提交结果。
- `input_version`：接收有效输入更新时递增；新增输入不自动使旧响应失效。
- `scene_id`、节点和关系 ID：持续存在，不以标题相似度代替身份。
- 每个输入证据绑定 segment revision，ASR 修正会使引用旧 revision 的判断待复核。

第一版不做复杂操作级并发合并：若 base graph 已改变，或请求引用的 segment revision 已被替换，拒绝整批响应，并用最新状态重新计算。未提交响应不能确认消费。重算前已经失效的关系停止作为确定关系呈现，直到重算完成。

判断“有新输入”与“旧证据被改写”必须分开。前者正常接续，后者重算，避免持续讲话导致结果饥饿。

`hold` 可以消费本次确已考虑的输入版本，但原文、暂定对象与未决摘要仍留在后续上下文中；后一句不能因前一句已消费而丢失主语或原因。

## 6. 上下文与有限回看

模型上下文包含当前图、当前场景及最近 4 个归档场景摘要、未消费 final、最新 partial、相关原话和未决点。每个关系都能追溯来源。

第一版原始上下文默认最近 120 秒或 3000 个中文字符以内，以先到的限制为准；当前对象、未决点和证据摘要独立保留。未消费 final 不能被这个窗口裁掉，应按顺序拆成有界请求，标出积压。严重积压必须可见，不能静默跳过。

会话输入账本保留到用户重置；模型请求只带有界窗口，不每次发送全部历史。第一阶段评测 5—10 分钟，不宣称 30 分钟或更长已经验证。

明确回指最近 4 个归档场景时允许修正归档，并保留当前展示；只有用户显式选择回看才跳转。不在可回看范围或指代不清时返回未决提示，不能猜测修改另一个观点。

输入文本是待解释资料，不得执行其中要求读取文件、发送消息等指令。真实控制使用独立 UI/control 事件通道。

## 7. 从语义图到画面

语义 Store 保留信息，Presenter 选择当前需要展示的一小部分。模型选择关系场景和重点；具体坐标由布局器决定，第一版不让模型自由给坐标、颜色和 HTML。

初始每场景最多 6 个可见节点和 8 条边。超出容量时，按完整观点分出续接场景，保留对象回指与已建立关系。不能靠 `slice()` 静默删除含义，也不能把所有文本缩小塞满屏幕。

新增节点、连接、焦点变化、关系替换分别有对应动画。文本修正只更新对应标签；稳定对象不重建、不重复入场。不能用整页 `innerHTML` 重写冒充局部动画。

保持画面时，输入与理解继续运行，Presenter 维持可见快照。恢复时从可见快照直接 diff 到最新有效状态，不把期间所有动画补播一遍。

语义模式不走旧 `provisional()` 的原话截断大标题，不让旧 `derive()` 的轮换底色与防重复版式影响当前场景。原话仍可在独立字幕区呈现。

## 8. 模型与失败处理

继续使用现有密钥配置入口，不能把 Key 暴露给浏览器。新 `/api/understand` 默认使用当前 `DIRECTOR_MODEL`，关闭思考，只返回一包完整 JSON。先不做图操作流式提前执行，避免半截 JSON 或后半包修正污染场景。

建议初始输出预算 900 tokens，最多 12 个操作，客户端/服务端超时分别设为 8s/6s，均允许配置；这些是待测起点。输出截断或校验失败整批不提交、不确认消费。超出可承载内容要分批，不用静默丢字段换速度。

无 Key、超时或非法输出：保留最后有效图与实时字幕，向讲者显示降级状态。不得声称本地规则理解了因果。暂态错误最多重试一次，仍失败进入可恢复状态，避免无限重试和重复计费；未消费内容留存并报告积压。

长篇思考、更大模型、图片生成均不是第一阶段的前置条件。先用实际结果验证 Flash，再判断瓶颈在语义、请求长度、ASR 还是网络。

## 9. 迁移与兼容

默认仍为现有模式；`?mode=semantic` 才启用新链路。`server.mjs` 增加新路由并复用现有本机 Host/Origin、类型与请求体边界，旧 `/api/direct*` 不改协议。

语义纯模块应能在 `node --test` 里导入；依赖 DOM 的测试另设最小夹具或浏览器检查。扩展 `npm run check` 覆盖新模块，不能只校验旧文件。

已有 open #8 与测试相关、#13 与旧导演流式响应相关。新任务引用它们但不据此自动关闭；是否满足原验收应另行核查。
