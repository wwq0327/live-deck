# [P1][S02] 建立版本化转写账本，正确处理 partial 替换与 final 顺序

状态：待开发。所属方案：持续理解与动态思维可视化 v1。

## 目标

持续保存听到的信息，partial 替换自己的草稿，final 不丢失，为跨句理解提供正确输入。

## 前置任务

无；可作为基础任务开始。

## 开发入口

建议新增 public/semantic/transcript.js 与纯函数测试；定义输入桥接接口，实际麦克风接线由 S08 完成。

先读 [开发交接](../HANDOFF.md)、[协议](../protocol.md)、[架构](../architecture.md) 与 [验收](../acceptance.md)。

## 工作范围

- 按协议实现 transcript 事件、input_version、稳定 segment_id/order/revision/speaker_id。
- 同一段的 partial 前缀整体替换，不追加重复文字；final 封口，迟到 partial 不得覆盖。
- 分配身份的接口要求在音频段/请求创建时捕获；不能用回调发生时的全局 state.seg 绑定旧响应。
- 按采集顺序整理乱序 final；支持更高 revision final 纠错、幂等与冲突检测。
- 提供未消费 final、最新 partial、来源查询与来源失效事件；记录与发送模型的上下文窗口分开管理。

## 验收

- [ ] 多次 partial 加一次 final 只形成一份该段内容；迟到 partial、重复事件和不同文本同 revision 均有回归。
- [ ] A/B final 倒序返回时讲话顺序不变；更高 final revision 可纠正并通知语义层。
- [ ] 来源查询能返回指定旧 revision 供历史检查，当前有效视图不混入被替换草稿；不以静音或标点作为唯一语义触发条件。
- [ ] 运行与本改动相关的检查，并完成 `npm run check`、`npm test`；报告真实执行结果与仍未验证项。

对应验收场景：C01、C02、C09、C10。

## 本项不包含

不更换 ASR 模型、不宣称原生流式识别、不改动默认页式链路的排队修复。

## 交付

一个聚焦 PR，链接本 Issue，说明输入输出、行为变化、验证证据和剩余限制。依赖未完成或验收缺失时保留 Issue 打开。模型无 Key 降级、接口连通与 mock 不能作为真实语义验收。
