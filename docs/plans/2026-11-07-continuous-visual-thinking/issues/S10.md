## 工作范围

- 执行 acceptance.md A—D 四层验证；真实调用与 mock 明确区分，真实模型评测显式由使用者开启。
- C01—C08 每例至少3次真实调用，原始操作/语义判定留档；标注必需/禁止关系、核心观点、否定/条件/设想状态。
- 至少两段60—90秒真实口播及一次5—10分钟连续使用；记录实际模型、设备、ASR、网络、参数、样本量。
- 记录语义上屏/调度/渲染耗时、final 完整消费、场景切换和重排、tokens/请求数；不复用旧文档延迟作为新模式结果。
- 目标 precision/recall及核心意思覆盖均>=90%，严重语义反转为0；语义上屏P50<=1.5s/P95<=3s，渲染P95<=100ms。未达标报告瓶颈，不删样本。
- 依据结果决定继续 Flash、缩短输出/上下文、优化 ASR 或比较其他模型；不先承诺更换模型必然改善。

## 验收

- [ ] 确定性测试和旧检查通过，真实模型逐例结果、视觉增量证据、真实语音记录齐全。
- [ ] 所有统计有口径和样本数；失败/降级/积压包含在报告，不能把预制最终画面或全稿输入当实时通过。
- [ ] 无 Key/无麦克风/缺人工视觉验收时记录已完成和缺项，保留本 Issue 与总任务打开。
- [ ] 运行与本改动相关的检查，并完成 `npm run check`、`npm test`；报告真实执行结果与仍未验证项。

对应验收场景：C01—C14，全层验证。

## 本项不包含

一个聚焦 PR，链接本 Issue，说明输入输出、行为变化、验证证据和剩余限制。依赖未完成或验收缺失时保留 Issue 打开。模型无 Key 降级、接口连通与 mock 不能作为真实语义验收。
