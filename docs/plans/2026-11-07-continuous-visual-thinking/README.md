## 1. 要解决的问题

人自然讲话时，重要的对象、因果、对比、组成和转折往往散落在多句话里。听众听过即逝，不一定马上理解结构；讲者也不方便边讲边制作图示。

用户当前测试反馈：画面主要将识别到的话汇集成文字，没有把跨句关系解释出来；分段收句、逐段思考的体验不连贯，后续补充也没有充分修正之前的理解。

目标：**系统边听、边维护可修正的理解，再用简单图示和有含义的动态变化，把讲话中的思路逐渐展示出来。**

“所想即所得”是体验方向。系统依据已表达的语言和上下文理解，不宣称读取未说出的内心，也不把自行推测包装成讲者结论。

## 2. 用户要求，开发时不可退化

1. 画面必须解释核心意思与关系，不能把“识别文字并排版”当作完成。
2. 持续听取、理解和展示并行；不必等待静音、句号或整段结束才开始处理。
3. 当前理解可被后文补充、否定、限定和修正，包括修改前面的关系。
4. 同一观点持续展开；一句话、一个 ASR segment、一个场景不是同一种边界。
5. 图形保持简单、友好、便于理解；优先使用可修改的节点、箭头、分组、堆叠和标签。
6. 动画表达关系的建立、汇聚、展开、强调或修正。装饰效果不能掩盖逻辑错误。
7. 速度重要，但不能通过丢掉中间新信息、删去否定条件或显示预测结论换速度。
8. 有预制模板。模板规定怎样表达关系、怎样增量更新，而不只是固定的一页排版。
9. 讲者能保持画面、恢复和纠正；不要求讲者用标准化制图口令讲话。
10. 用户以 DeepSeek Flash 实施开发；交接必须有明确协议、依赖、输入输出与验收。

## 3. 第一阶段范围

在现有 Node.js 项目上增加可选的 `?mode=semantic` 模式，原模式继续可用。

第一阶段完成：持续输入事件账本、可修正语义图、四种关系场景、局部渲染、实时调度、有限历史修正、保持/恢复/重置、回放与真实模型评测。

四种场景：因果、对比、组成、汇聚。顺序、条件、问题等信息必须能保留；暂没有专用图形时使用中性文本表达，不能强行改画成因果。无关系的短观点允许用重点文字呈现。

多人场景在协议中预留 `speaker_id`；完整说话人分离及观点归属评测放到后续 Issue。第一阶段用单讲者验证，不能宣称多人对谈已完成。

暂不纳入第一阶段：现场生成复杂插画、任意 HTML 生成、通用 PPT 编辑器、PPTX 导出、云端语音、全新语音模型、长会无限记忆。图片标注与素材异步接入另立后续任务。

## 4. 视觉方向

沿参考片段设计独立的深绿色主题：低对比背景纹理、白色正文、绿色强调、简单几何对象。参考研究截图仅用于分析，不直接作为产品素材。

每个场景原则上控制在 3—6 个可见对象、最多 8 条关系。内容超出时按观点拆出续接场景，保留语义账本与回指，不能静默截断信息。这个数量是初始设计上限，验收后可调整。

已有对象位置尽量稳定；新增对象进入，关系逐段连接；修正只改变相关对象。提供减少动态效果模式，其语义与普通模式一致。

## 5. 技术方向与事实边界

- 保留 Node.js、现有本地 ASR 与浏览器 DOM/SVG 渲染，不引入新的应用框架或视频渲染框架。
- DeepSeek Flash 先作为语义导演候选，短 JSON 操作、关闭思考；不让模型逐次生成整页 HTML。
- JSON 合法只说明结构可解析，不保证关系理解正确；必须另做语义评测。
- 本轮不调用付费模型、不新测延迟。现有文档的历史耗时不作为新模式的性能承诺。
- 参考成片可以证明同步展示与渐进变化，无法证明作者现场实时生成或使用某个工具。

官方能力参考：[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。参数与模型版本在实际开发时重新核验。
