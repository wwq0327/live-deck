# 验收场景与评测方法

状态：待开发验收要求。下面都是**人工设计的测试输入与预期**，不代表模型已经通过。

## 1. 验证分层

| 层 | 要证明什么 | 不能替代什么 |
| --- | --- | --- |
| A：确定性模块/竞态测试 | 输入替换、原子操作、来源、版本、合并、恢复正确 | 不能证明模型听懂了 |
| B：真实 Flash 语义回放 | 对象、关系、转折、条件和纠正符合讲话 | 不能证明麦克风端到端表现 |
| C：浏览器视觉检查 | 稳定对象、关系清晰、局部动画、无溢出 | 不能证明关系符合原意 |
| D：真实语音 | 连续讲话、ASR 修正、端到端速度和恢复 | 不能由整段文本一次输入替代 |

回放必须按事件时间逐条开放内容。可以事先载入 fixture 以便播放，但送给模型的 sources/context 只能包含此刻已到达的事件。预期图、未来文字与检查点答案不得进入模型提示。

## 2. 必测场景

每个 fixture 保存 `id/events/checkpoints`；事件字段遵循 [protocol.md](protocol.md)。检查点用必需关系、禁止关系、核心观点和状态描述，不要求模型逐字复刻标题。

### C01 连续讲话，跨句因果

同一 seg 的 partial：0ms「资料放在微信」；1000ms 替换为「资料放在微信、文档和表格里」；2200ms 替换为「资料放在微信、文档和表格里，所以找东西时我得来回切换」；4000ms final 补充「切换让我花更多时间」。这是模拟事件时间，不是 ASR 实测速率。

预期：无静音也能在 final 前产生语义请求；对象不重复；明确因果后形成“分散存储 → 来回切换 → 耗时”。不能在第一条 partial 时提前生成后续因果或用逗号位置决定箭头。

### C02 ASR 修改否定

partial rev1「这个办法能减少切换」；final rev2「这个办法不能减少切换」；再送迟到 partial。

预期：账本替换文本，依赖 rev1 的正向关系失效并重新评估；迟到 partial 不覆盖 final；不得删掉“不”维持旧图。

### C03 跨句纠正原因

「用户流失是因为操作太复杂。」→「准确说，是新用户找不到入口。」→「老用户没有这个问题。」

预期：同一场景修正原因、限定人群，保持核心问题；不能变成三页互不相关的大标题，不能把新老用户都画为受影响。

### C04 先后不等于因果

「我们先换了界面，后来用户增长了。不过我还不能确定两者有没有关系。」

预期：保留先后和不确定性；禁止界面改动 causes 用户增长。可用中性文字或时间顺序，不强套因果场景。

### C05 提问不是断言

「会不会是价格太高，才导致用户流失？」

预期：question/hypothesis 明确，不能画成已经确认的原因。不能因一句话同时出现两个名词就自动连实线。

### C06 方案不是已验证结果

「我想做一个统一入口，希望减少切换，效果还需要试。」

预期：proposal；虚线或明确标签表达待验证，不生成“已经提高效率”或虚构提升比例。

### C07 转折与否定

「我以前觉得速度最重要，后来发现，理解内容比速度更重要。」以及「不是低价带来增长，是新入口带来了更多访问。」

预期：原判断与当前判断有区别；后一例撤回/排除低价原因，表达新入口原因。不能把两个原因并列保留为同等成立。

### C08 概数和原话边界

「最初几万，后来几千，现在只有几十，大概是这个量级。」

预期：保留概数与口述性质。第一版可用文字对照；不得伪造精确数值、外部统计来源或严格比例坐标。

### C09 换主题、迟到结果和重置

延迟 A 请求；切入 B 场景或执行重置；再返回 A 的结果。另测只有输入继续增长、旧来源未变的情况。

预期：前者不得污染新 epoch/不匹配版本；后者允许有效响应提交再接续新输入，不能持续全丢导致永远没有图。

### C10 持续负载与完整消费

受控导演每次延迟 1500ms；每 500ms 来一条新事件，包含独立的中间观点及多次 partial 替换，持续 60 秒。

预期：最多一个在途语义请求；partial 合并，全部 final 信息进入成功消费或明确未消费积压；不能只保留最后一句，也不能逐页补播所有历史输入。停止输入后能够在有限请求中排空，超限/失败可诊断。

### C11 无 Key、超时、非法操作

分别模拟无 Key、上游超时、空内容、截断 JSON、不存在的端点、假证据、未知 op 和重复响应。

预期：整批拒绝或明确降级；最后有效图和字幕仍可用；不确认消费失败输入；无部分应用、无无限重试、恢复后可继续。

### C12 原位更新与可理解动画

因果链逐段延长；五层组成逐项补充；对比补充共同维度；多个来源汇聚。更新一个标签或撤回一条边。

预期：已有 DOM/SVG 身份和位置稳定，只有受影响部分更新；不重复全页入场；普通模式与 reduced-motion 语义一致；1600×900 与 1280×720 均可阅读。

### C13 容量续接与核心意思

同一主题给出超过 6 个对象或 8 条关系，随后回指最先提到的对象。

预期：按观点续接并保留回指、关系与 receipts；不能静默 slice 掉信息，不能只为了防重版式换皮。人工确认主张与限制条件没有被摘要丢失。

### C14 保持、恢复和有限历史修正

保持画面后继续输入并纠正；恢复；显式修正上一场景；再提一个已超出回看范围的模糊回指。

预期：保持期间后台继续，恢复直达最新有效状态，不补播积压动画；修正归档不自动打断当前画面；范围外指代不明时明确未决，不猜目标。重置清除在途请求与会话状态。

### C15 多人观点冲突（后续 S11）

带可靠 speaker ID：甲「我觉得价格是主要原因」；乙「我不同意，主要是入口不好找」。再用 unknown speaker 输入同样文字。

预期：保留说话人归属与分歧，不把两人意见合并为同一个人的前后自我纠正；unknown 时不猜身份。真实音频的说话人分离质量需另测。

### C16 异步素材过期（后续 S12）

请求 A 素材后换到 B；返回 A；另测获取失败、恢复匹配场景及标注更新。

预期：素材只接入匹配的 scene/epoch；失败不阻塞关系图；图片不能改变已确认语义或引入未授权素材。

## 3. 指标口径

记录 `audio_end → transcript_received → request_started → response_validated → graph_committed → first_visible_frame`。语义可判定时刻另由 fixture 检查点或人工标注，不能把开口、收句、首包 token 当成同一时间。

- 语义延迟：关系首次有足够语言依据，到该关系有效上屏。
- 调度延迟：新语义输入到请求开始；忙碌时单独计入等待。
- 渲染延迟：有效图提交到首帧；保持画面期间单独标记，不纳入正常上屏延迟。
- 关系 precision/recall：按人工标注的可接受关系集合核对；支持同义概括，不要求固定标签。问题/方案的状态、方向与条件也算正确性的一部分。
- 核心意思完整性：检查点主张、关键范围与否定条件是否保留，不能只用边数量代替。
- 还记录：final 未消费数、积压年龄、重算/拒绝原因、场景切换数、全局重排数、请求数、输入/输出 tokens。费用仅使用实测 tokens 和当时官方价格计算，不称“可以忽略”。

## 4. 第一阶段建议门槛

以下是待验证目标，开发者不能提前宣称达成：

1. A 层 C01—C14 相关确定性断言全部通过，旧 `npm run check` / `npm test` 继续通过。
2. B 层 C01—C08 每例至少真实调用三次，报告每次结果；关系 precision 和 recall 均 ≥90%，全部检查点核心意思覆盖 ≥90%。禁止关系、否定反转、设想变成果等严重失真为 0。样本仅说明这组验收，不外推普遍能力。
3. C 层 C12、C13 人工逐项通过，截图与至少一段连续录屏留档；预制最终画面不能替代增量录屏。
4. D 层至少两段 60—90 秒真实口播（含无明显停顿与回头纠正），另一次 5—10 分钟连续使用；记录设备、ASR、模型、网络与配置。
5. 初始性能目标：真实语义上屏 P50 ≤1.5s、P95 ≤3s；有效图提交到可见帧 P95 ≤100ms。每个统计注明样本数。达不到就报告瓶颈，不能靠丢输入、隐藏错误或改为整段离线处理通过。

不要求本轮方案制定者运行上述测试。没有真实 Key/麦克风/人工视觉验收时，保存已通过项与未完成项，保留总 Issue 打开。
