# 架构

一句话：**把"生成一份幻灯片"拆成"每半秒钟做一个小决定"，再把每个小决定压到几十毫秒。**

## 非目标

先写清楚不做什么，很多设计取舍都是从这里来的：

- 不做"生成整份 PPT"。没有大纲、没有主题套用、没有导出 pptx。
- 不用 agent，不让模型调用工具。一次请求 = 一条 JSON 指令，不迭代、不反思。
- 不做云端语音。音频不出本机。
- 不做复杂图形。能画的是文字、色块、线条、十几个内置符号；要真图表就走慢车道（见 roadmap）。

## 组件

```
┌──────────────────────── 浏览器（零构建） ────────────────────────┐
│  index.html                                                      │
│  stage.js     AudioWorklet 采集 → VAD 切句 → 字幕 → 状态机        │
│               derive() / layoutHTML() / show() / morph()          │
│  stage.css    13 构图 × 3 底色                                    │
└───────────────┬──────────────────────────────────────────────────┘
                │ POST /api/asr?mode=partial|final    (WAV, 16k mono)
                │ POST /api/direct                    (JSON)
┌───────────────▼──────────────────────────────────────────────────┐
│  server.mjs     静态文件 + 两个 API，净身无依赖                    │
│  asr.mjs        spawn 一个 Python 常驻进程；两条优先级队列         │
│  director.mjs   提示词 + 一次 chat/completions + JSON 归一化       │
└───────────────┬──────────────────────────────────────────────────┘
                │ stdin/stdout 逐行 JSON
┌───────────────▼──────────────────────────────────────────────────┐
│  asr_worker.py  模型常驻内存；SenseVoice(sherpa-onnx) / whisper    │
└──────────────────────────────────────────────────────────────────┘
```

没有数据库、没有消息队列、没有构建步骤。整个仓库 `node server.mjs` 就能跑。

## 一次说话的完整时序

假设讲者说："以前做一份演示要花三四个小时，现在只要开口。"（约 6 秒）

| 时刻 | 发生什么 | 谁做的 |
| --- | --- | --- |
| 0.0s | VAD 检测到能量跨过阈值（`rms > max(0.012, noise×2.8)` 持续 0.1s），开一段录音，带 0.4s 预录缓冲 | stage.js |
| 1.0s | 攒够 1.0s 音频 → 发 `mode=partial` | stage.js |
| 1.05s | SenseVoice 返回半句（约 50ms） | asr_worker |
| 1.06s | 字幕滚动；字数 ≥8 → `provisional()` 立刻渲染一页占位（**0 调用**） | stage.js |
| 1.07s | 同一段半句丢给导演（`prethink`），结果存 `state.ahead` | server → LLM |
| 2.1s | 导演返回 → 和占位页是同一句 → `morph()` 原地改写（0.34s 软过渡） | stage.js |
| 2.4s | 第二个 partial → 更准的半句 → 再 morph 一次 | … |
| 6.3s | 静音累积到 0.42s → 收句；取消还在跑的 partial（它只是预览），发 `mode=final` | stage.js |
| 6.45s | 整段转写回来（0.05–0.14s），final 不再排在 partial 后面等 | asr_worker |
| 6.5s | `decide()`：把"刚说的这一句"发给导演 | server → LLM |
| 7.8s | 定稿页回来；同一句话 → morph；话题变了才 `show()` 翻页 | stage.js |

**用户感知**：说到第 1 秒画面就开始动，说完的时候画面已经在了。HUD 上的 `0.00s · 预生成` 就是这个意思——收句之后没有再等。

partial 只负责“预览”：收句时前端会直接 abort 还在跑的 partial，server 也会丢弃排队中的 stale partial，final 不再等它们；预判结果带 segment 号，收句后自动过期，避免定稿后又被旧半句翻出一页。没有 partial 的短句或打字输入，`commit()` 也会先本地 `provisional()` 上一页，再等模型回来原地改写，首屏不再空等一次导演调用。

## 状态机

### 句子（segment）

```
        ┌──────── idle ────────┐
        │  rms > thr 连续 0.1s  │
        ▼                      │
     recording ──每 1.0s──► partial
        │                      │
        │  静音 ≥0.42s 或段长 >20s
        ▼                      │
    closing ──final 请求──► decide ──► idle
```

- 段长 < 0.45s 直接丢（"嗯""对"这种）。
- partial 结果 < 6 字丢弃（太短的片段转出来全是错字）。

### 页面（page）

```
show(raw) ── derive() ──► 新 section 入场（clip 0.95s）
   │                         │
   │  同标题？               │  同一句话内的更新
   └──► morph() ◄────────────┘
          │
          └─ 页面存在 <2.4s：允许换构图
             >2.4s：锁定构图，只改文字
```

- `morph()` 不新增页、不重排入场动画，只把当前 `section` 的 `className` 和 `innerHTML` 换掉，并加 `.soft` 把过渡压到 0.34s。
- 旧页淡出 420ms 后移除，中间没有空白帧。

## 三个并发来源，和它们打架的地方

页面的输入有三路，速度不一样：

1. `decide()` —— 收句后整段转写，最准，但最晚。
2. `ahead` —— 说话过程中拿半句问的，快，但可能不准。
3. `predict` —— 出页后预判下一句，只用来抢 0ms。

它们会互相覆盖。踩过的坑和解法：

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| 一句话翻出 3 页 | 上一句的 ahead 在下一句开讲后才返回，此时 `state.live` 已清空，于是凭空 `show()` | `prethink()` 记录 `state.seg`，返回时 `seg !== state.seg` 就丢弃 |
| 同一句翻出两页一样的 | 收句后 `state.live` 被下一句清掉，`decide()` 以为没有活页 | `closeSegment()` 把 `live` 拍成快照，一路传进 `finishSegment/commit/decide` |
| 定稿页跟占位页长得一样 | 导演以为"当前页已经讲过了" | 给导演传 `current.provisional=true`，提示词允许整页重写 |
| 两句话共用一个页面的一半 | `state.busy` 期间又来了一个 `commit` | `state.pending = {t0, snapshot}`，忙完再跑 |

一句话总结：**每个异步结果都必须带着"我是哪一句的"出发，回来时要对得上号。**

## 延迟预算

想做到"听起来同步"，端到端不能超过 1–1.5 秒。预算表（SenseVoice）：

| 段 | 耗时 | 备注 |
| --- | --- | --- |
| VAD 判定收句 | 420ms | 唯一"必须等"的部分，也是主要延迟来源 |
| WAV 编码 + 上传 | 5–20ms | 本地回环，16k 单声道，一句 100–300KB |
| SenseVoice 推理 | 50–140ms | int8、2 线程、CPU |
| 导演推理 | 600–1300ms | `thinking.disabled`，输出约 120 token |
| 渲染 | <50ms | 纯 DOM 模板 |

关掉思考链是这里最大的一笔：同一个模型、同样的提示词，开着思考要 1.9–2.6s，关掉 0.6–1.0s。

## 降级路径

- **没有 Key** → `director.mjs` 的 `heuristic()` 用关键词出页（数字→stat、对比词→compare、序数词→steps），不报错。
- **ASR 没就绪** → `transcribe()` 最多等 20s（模型加载中）；如果 worker 已经退出，会立刻带着具体原因失败，前端字幕显示 `本地转写失败：…`。
- **ASR 进程挂了** → `asr.mjs` 把 `ready=false`，所有 pending 直接 reject；下次请求会重新 spawn。
- **导演超时** → 9s 中止，回退到启发式。前端照旧渲染，只是这页不"聪明"。

## 为什么不是 agent

试过让 agent 边聊边生成 HTML 页面（慢车道）。问题不是能力，是**节奏**：agent 一轮 5–15 秒，而听众的耐心是 1 秒。

所以现在的分工是：**快车道**（这条管线，1 秒内）负责"跟上"；**慢车道**（agent 离线生成富媒体页）负责"讲得深"，生成的页塞进队列等下一个合适的停顿。快车道永远不阻塞。
