# S07 · 四类关系场景与主题

日期：2026-11-07
Issue：#28
分支：`codex/semantic-mode`

## 本次范围

把通用布局升级为四种关系模板，并补上容量提示与组成容器。S06 的稳定 ID 渲染器保持不变，S07 只改布局/呈现，不改 Store、调度与模型协议。

| family | 模板 | 有向箭头 |
| --- | --- | --- |
| `cause` | 从左到右的因果链，rank 最长路径分列 | 是（`causes`） |
| `compare` | 成对左右并排，围绕同一行的对比轴 | 否（`contrasts` 虚线无箭头） |
| `composition` | 多个部分时用容器 + 右侧汇流括线；单链时按层展开 | 部分→整体，一处箭头 |
| `convergence` | 来源左列堆叠，目标右列，多线汇入 | 是（`converges_to`） |
| `text` | 单列中性文本；`sequence`/`conditional` 走侧向通道 | 视关系而定，不强行因果 |

## 实现

- `public/semantic/layouts.js`
  - `layoutScene` 按 family 分派，返回 `{nodes, edges, groups, capacity, targets, width, height, kind}`，过滤 retracted 与端点缺失的边。
  - `capacity`：`nodes`/`edges`/`max_nodes=6`/`max_edges=8`/`exceeded`；**不删除任何节点或边**，超出仅由渲染器提示续接。
  - `layoutCompare`：按 `contrasts` 配对，左右并排、`dir='compare'`、水平虚线轴、标签居中；没有对比边时两两成行。
  - `layoutComposition`：若某整体有 ≥2 个部分，生成 `.sem-group` 容器（整体在顶部，部分纵向堆叠），右侧一条竖向括线收拢所有部分并以单箭头进入整体；否则按 part→whole 链式分层，保留每一层。
  - `layoutConvergence`：来源左列、目标右列（约 62% 宽处），所有 `converges_to` 曲线汇入目标，同一目标只显示一次关系词。
  - 同列关系（text/cause 中上下相邻）改走右侧通道，避免被卡片遮住箭头。
- `public/semantic/renderer.js`
  - 新增 `.sem-groups` 层与 `#reconcileGroups`（按 `g_<wholeId>` 复用容器），容器与节点同样走 keyed 更新。
  - `.sem-capacity` 提示仅在 `capacity.exceeded` 时显示：“内容超出单场景容量，将按观点续接（未丢弃）”。
  - 汇聚目标加 `is-target`；边支持 `arrow:false`（组成括线只保留一个箭头）。
  - 每次渲染重新测量容器尺寸（修复缓存尺寸导致的 DOM 与 SVG 坐标错位）；节点设置固定 `height`，避免内容撑高后与布局重叠。
- `public/semantic/theme.css`：容器、容量提示、目标高亮、compare/converge/part 边样式。
- `public/semantic/preview.js`：13 步演示，依次覆盖因果、对比、组成逐层增加、汇聚、问题/设想中性文本、减少动态；仍只用 9 类静态操作，无模型调用。

## 验证

- 单元测试：`test/semantic-renderer.test.mjs` 19 项，包含
  - 对比并排、`dir='compare'`、标签在轴上、无因果箭头方向；
  - 组成容器包住整体与部分、组成默认不重复“组成”标签；
  - 一层到五层组成旧层全部存在且 x 递增；
  - 汇聚来源在目标左侧、`targets` 正确；
  - 7 个节点时 `capacity.exceeded=true`、布局仍返回 7 个节点、渲染器提示续接；
  - 增加部分时容器与既有节点元素引用不变。
- 全量：`npm test` 113 项通过；`npm run check` 通过。
- 浏览器（bsk 会话 `wclv`，Chrome）：
  - 1600×900：cause / compare / composition / convergence / text 逐场景截图；
  - 1280×720：组成场景无溢出、容器与括线对齐；
