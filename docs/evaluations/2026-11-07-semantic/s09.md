# S09 · 保持与恢复、有限历史、人工更正

日期：2026-11-07
Issue：#30
分支：`codex/semantic-mode`

## 行为变化

- `?mode=semantic` 页面出现控制条：保持画面 / 继续更新、回到当前、最近 5 个场景 chip、未决 N。
- 保持只冻结可见画面：账本、调度器、模型请求继续运行；保持期间收到的理解结果只更新 Store，`markVisible` 不再触发。
- 继续更新时直接从 Store 最新状态渲染，`animate:false`，不补播保持期间的中间帧；保持期间提交的次数显示在状态里。
- 回看归档场景只切换展示（`renderer.showScene`），不改变 `active_scene_id`，也不打断后台理解；点“回到当前”或再点当前 chip 取消回看。
- 节点/边可点击或键盘聚焦后按 Enter/Space 打开轻量更正：改文字、改说法/关系、撤回（二次确认）。更正走 `store.applyManual`，只递增 graph_version，不新建对象；被更正的节点/边带“人工”标记并写入 ARIA。
- 指代不清的回指由模型返回 `hold + unresolved`，页面显示未决数量，不猜目标；reset 关闭抽屉、清空视图、epoch+1。

## 实现

- 新增 `public/semantic/presenter.js`：`SemanticPresenter` 负责保持/恢复、回看、人工更正，渲染器只负责画。
- 改 `public/semantic/app.js`：HUD、场景 chip、未决提示、更正抽屉、键盘事件委托、presenter 状态映射。
- 改 `public/semantic/renderer.js`：节点/边 focusable + ARIA、`data-manual`、人工 flag。
- 改 `public/semantic/store.js`：`graphView()` 暴露 `manual`，让模型看到人工更正。
- 改 `semantic-director.mjs`：默认输出预算 900 → 1400 tokens；提示词增加“只输出增量”“新观点建续接场景”“模糊回指不猜”“尊重 manual 对象”四条规则。
- 新增 `test/semantic-presenter.test.mjs`（6 项）；Store 增加归档场景人工修正、撤回级联两项；渲染器增加键盘/人工标记一项。

## 验证

- `npm run check` 通过。
- `npm test`：123 项全过（0 失败）。
- 浏览器（Chrome，1600×900，真实 DeepSeek Flash，`bsk` 控制）：
  - 两个场景后 HUD 显示两个 chip，当前 chip 有 `is-current`。
  - 点归档 chip：标题与节点切到旧场景，`active_scene_id` 不变，出现“回到当前”；点回当前恢复。
  - 键盘 Enter 打开更正抽屉，改标签保存：label 更新、`data-manual=true`、flag“人工”、graph_version +1、active 不变。
  - 保持后输入新观点：DOM 保持旧场景，Store 增加场景，状态“已保持 · 后台继续”；继续更新后直达最新场景，`.sem-enter` / `.sem-draw` 为 0。
  - 在途人工更正：请求发出 600ms 后改标签，旧响应返回后未覆盖；重算后归档场景仍保留人工标签，`manual=true`，graph_version 只 +1。
  - 模糊回指“前面那个东西还是不对”：场景数不变，`unresolved` 记录指代不清，HUD 显示未决，halted=null。

## 已知限制

- 真实模型中仍会出现重复场景（同一主题被再次 `create_scene`）与把历史未决项一次性重复返回；属于理解质量，S10 评测记录，不在 S09 内静默删除。
- 输出超过 12 ops 会被整批拒绝并 halt；已通过提示词约束“只给增量”，但极端长段落仍可能触发，S10 继续观测。
- 本 Issue 未做真实语音长会、未做人工视觉验收；整体验收仍以 S10 报告为准。
